# 四向律动 1.1

Native Qt Quick game module; moduleId=rhythm, effector=2. The session begins with a settings screen and then runs the existing five rounds.

## Difficulty presets

| Difficulty | BPM | Directions | Base note interval | Judgment window |
|---|---:|---|---:|---:|
| Teaching | 70 | left/right | about 1.71 s | ±0.55 s |
| Standard | 90 | four directions | about 1.33 s | ±0.40 s |
| Challenge (keyboard practice) | 110 | four directions | about 1.09 s | ±0.30 s |

The engine rounds note gaps to beats and also enforces a non-overlapping judgment window. Each round logs the complete note chart and measured first interval. Long-note rounds use a wider actual interval to preserve the hold duration. BCI sessions default to teaching; faster BCI timing needs a separate decoder-window and recovery-time calibration and is not represented as clinically validated.

## Audio

Background music, beat cues, and note-result sound effects have separate controls on the setup page and during play. Audio state changes are logged with task time and do not reset the chart or engine clock. Pause suspends the music player; resume continues it; session completion and stop release it.

The eight-bar, 90 BPM background loop is an original procedural synthesis. It uses no recordings, samples, or third-party compositions. Recreate it with python tools/generate_background_music.py; the source is tools/generate_background_music.py and the generated asset is audio/background-90bpm.wav. Playback rate follows the selected difficulty and the final round's BPM changes. Short cues are generated by tools/make_audio.py.

Audio-device availability and output latency depend on the deployment machine. An audio playback failure is logged and does not stop timing or scoring. This environment has no audio output device, so physical output latency still needs measurement on the target host.

## Boundaries

RhythmEngine.js remains the sole timing and scoring authority. Input records describe game commands; they do not measure EEG decoding accuracy or clinical outcomes. Use node tests/test_engine.js for engine logic and python tests/verify_qt.py for GUI/host integration when running validation.
