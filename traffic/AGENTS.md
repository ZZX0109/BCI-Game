# traffic V4 不变量与约束

## 不可更改的接口

- `moduleId` 必须为 `"traffic"`。
- `effector` 必须为 `2`（GamepadLite）。
- 必须保留 `taskContext` 和 `game` 两个 required property。
- 必须响应宿主信号：`onStarted / onStep / onAction / onPaused / onResumed / onStopping`。
- 整场会话只能调用一次 `game.finish()`。

## 世界坐标与物理约束（V4 核心）

- `crossX` / `travelY` 是世界坐标真值；**屏幕像素绝不能作为碰撞判据**。
- 玩家与车辆的位置推进必须使用 `onStep` 提供的模拟时间与固定子步（`substep = 0.008`），
  禁止用 QML 动画或定时器代替物理推进。
- 前进/后退必须支持"按住持续、松开停止"，不得改成"按一下自动播放整段过街动画"。
- 暂停时必须冻结玩家与全部车流；恢复不补算暂停时间。
- 切换关卡/重试必须清空 `cars` 与逐车道事件游标，不得残留上一关车辆。

## 车流约束

- 每车道车流必须由种子预先生成，禁止逐帧抛随机数。
- 生成后必须执行最小安全间隙校验（`PASS_MIN_CLEAR = 1.05s`），不得产生必死车流。
- 车辆必须在到达边界后离开并持续有新车辆生成，禁止只放固定几辆车。

## 行为与记录约束

- 碰撞失败不得宣称「神经抑制失败」，也不得据此推断脑电解码结果。
- 必须记录输入来源（`local` / `bci`），不得用一个未定义的 held 值通吃所有输入模式。
- 脑控慢速参数（`bciCarSpeedScale`）必须独立记录，不得把临床参数伪装成普通键鼠参数。
- 每次 `level_started` 必须带上该关车流配置与前若干条穿越事件，保证可离线回放核对。

## 视觉约束

- 使用 1000×700 设计坐标；街道场景 700×470，右侧状态面板并列。
- 车道、斑马线、车辆、行人都必须经过同一套 `projX/projY` 投影。
- 不使用 QtQuick3D。
